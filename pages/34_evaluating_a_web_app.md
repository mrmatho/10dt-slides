# Vocabulary: Effectiveness

How well something does the job it is meant to do.

**Example:** We measured the effectiveness of the design by testing how well users could complete the task.

**Similar word:** success

---
layout: center
---

# Vocabulary: Efficiency

How well something works while using the least time, effort or resources.

**Example:** The new printer has better efficiency because it uses less ink and prints more quickly.

**Similar word:** productivity

---
layout: center
---

# Vocabulary: Evaluation

Looking carefully at something and judging how good, useful or successful it is.

**Example:** Our evaluation of the design showed that it worked well but needed some improvements.

**Similar word:** review

# How to evaluate a web app

|                     | Effectiveness                                          | Efficiency                                                 |
| ------------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| **Question to ask** | 'Does it do what it was supposed to do?'               | 'Does it do it well?'                                      |
| **How to measure**  | Against the functional and non-functional requirements | By how quickly and smoothly users can complete tasks       |
| **Example**         | A user can add a new record.                           | A new record can be created in fewer than 3 clicks.        |

# Evaluation examples

- **Effectiveness** (does it work as intended?) – The Edit form updates the CSV correctly and the new details show on the master view after saving.
- **Efficiency** (how smoothly does it work?) – The navigation bar lets users move between pages in one click, reducing unnecessary steps.

# Changes needed before going online

Our app runs on our own computer. Before putting a web app online for real users:

- **Turn off debug mode** – debug error pages show your code to anyone (Lesson 2).
- **Use secure connections (HTTPS)** – so form data, like passwords, can't be read as it travels.
- **Test on mobile and different screen sizes.**

# Feature improvements that help users

Improvements should fix gaps found during testing and evaluation. Each improvement needs a **clear benefit** for users.

| Improvement                                         | User benefit                           |
| --------------------------------------------------- | -------------------------------------- |
| Add a search bar                                    | Helps users find data faster           |
| Add an "Are you sure?" check before deleting a record | Reduces the chance of accidental deletion |

# Guided practice: Evaluating effectiveness

Evaluate one requirement for effectiveness.

1. Choose a functional requirement.
2. Find the evidence in your testing log.
3. Decide whether the requirement was **met**, **partially met** or **not met**.
4. Write a short effectiveness evaluation on your mini-whiteboard:

> *My application is effective / needs improvement because…*

# Guided practice: Evaluating efficiency

Let's do it together.

1. Choose one action from your usability testing.
2. Use your evidence to judge how easy or difficult it was for the user.
3. Write a short efficiency evaluation on your mini-whiteboard:

> *My application is efficient / needs improvement because…*

# Summary

- **Effectiveness** is about whether an app does what it is meant to do.
- **Efficiency** is about how quickly and smoothly the app works.
- We used evidence from our testing to judge whether our app met its requirements.
- We used evaluation to identify useful feature improvements and explain how they help real users.
